# Security Policy

Resilience Copilot is designed for high-risk human-review workflows. Please treat safety issues as security issues when they could cause misleading, unsafe, or unauditable outputs.

## Supported Version

| Version | Supported |
| --- | --- |
| v0.1.x | Yes |

## Report a Safety or Security Issue

Open a GitHub issue if the report can be public. Use the safety improvement template when possible.

Good reports include:

- the case note or scenario that triggers the problem;
- the expected safe behavior;
- the observed unsafe or unclear behavior;
- whether the issue involves diagnosis, invented capacity, unsupported resource claims, emergency-service replacement, or missing human review;
- a minimal reproduction path.

If a report includes private personal data, do not publish the case note. Replace sensitive details with a synthetic example that preserves the failure mode.

## Safety Boundary

The public demo and docs are not emergency guidance. The project is a software pattern for auditable human-reviewed workflows, not a live responder, medical tool, or official resource directory.
